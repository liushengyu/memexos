# 来源分类标准（领域 · 专业 · 怎么用）

> 版本 v1（起步版）。每份来源都分一次类，之后才能用对：交易视频里的数字不能拿去论证别的事，作品展示不是技术事实，第三方转述不是一手结论。
> 下面的领域表只是**起步模板**，会从你自己的资料里长出来：放不进的资料先归进草稿，草稿攒够真实资料后交给你批准（见「新分类怎么产生」）。表可以随意改。

## 为什么要分类

知识库里的来源横跨很多领域，性质差别也很大：有人亲手实测的、官方原作者讲自己东西的、第三方转述的、个人观点、带货推广、纯作品展示。
分类回答四个问题：**它属于哪个领域、专业到什么程度、能拿来做什么、能信几分**。

## 六个维度

### ① 领域（`domain` 一个主领域，`secondary` 0~2 个副领域）

写成 `一级/二级`，从下表选：

你自己项目的会话和文档，也按它们**讲的是什么**选领域。

### ② 内容类型（`content_type`，选一个）

`教程实操`（手把手做出来）· `原理讲解`（讲清为什么）· `课程讲座`（系统课、公开课、讲座）· `实测评测`（亲手试、对比、跑数据）·
`案例复盘`（一个项目或产品怎么做成 / 做砸的）· `访谈对话` · `观点评论` · `资讯动态`（发布、新闻、盘点）·
`作品展示`（展示效果、几乎不讲做法）· `工具介绍`（介绍一个工具 / 项目是什么）· `论文研究` · `项目记录`（你自己的会话快照和工作文档）

### ③ 专业程度（`level`）

`入门`（没有基础也能看）· `进阶`（要有本领域基础）· `专家`（前沿、源码级、研究级）

### ④ 证据强度（`evidence`，决定引用时能信几分）

| 值 | 含义 | 编译和回答时怎么用 |
|---|---|---|
| `一手实测` | 作者（或你自己）亲手做过、跑过，给了过程或数据 | 可以当事实依据，写清是谁在什么条件下测的 |
| `官方或原作者` | 产品官方、论文作者、开源项目作者本人讲自己的东西 | 可以当事实依据；注意可能有立场 |
| `学术研究` | 论文、学术课程 | 可以当事实依据，注明是研究结论 |
| `第三方转述` | 搬运、翻译、盘点、二手解读 | 写成“据某某转述 / 盘点”，关键数字标 `⚠️ 待核实`，尽量找原始出处 |
| `个人经验观点` | 作者自己的经验、判断、心得，没有给出可核对的依据 | 写成“作者认为 / 经验之谈”，不当普遍结论 |
| `营销推广` | 带货、课程引流、产品自夸 | **不能当证据**；只记“有这个产品 / 说法” |

### ⑤ 用途（`usage`，可多选）

`学技能` · `查原理` · `查事实数据` · `找灵感参考`（看效果、找方向，不从中取技术事实）· `跟踪动态`（某个时点的状况，会过期）·
`选型参考` · `决策复盘`（你自己做过的决策和教训）

### ⑥ 时效（`durability`）

`长期`（原理、方法，几年内都成立）· `一年内`（工具用法、版本细节）· `时效短`（新闻、价格、榜单）

另外两句话：
- `scope_note`：**适用边界和注意事项**，一句话。例如“只对某个产品版本成立”“数字都是作者自述”“演示的是效果，做法没讲”。没有要说的写空字符串
- `summary`：这份来源是什么，一句话（目录里显示用）

## 判断要点

- 先看内容本身（标题、简介、正文或转写稿开头、画面补充的概览），不要只凭标题
- **专业程度和证据强度是两回事**：专家级的源码解读也可能是第三方转述；入门视频也可能是一手实测
- 同一门课的不同集是 `课程讲座`，分类应一致
- 只有效果没有做法的（作品合集）是 `作品展示`，用途 `找灵感参考`
- 带推广但主体内容扎实的，证据强度按主体内容定，在 `scope_note` 里注明“含推广”

## 新分类怎么产生（草稿 → 待审核 → 正式）

**分类时领域怎么定**
1. 配置了快速判断模型时先由它初筛：给每个正式分类和草稿打分，再单独判断最可能的那个分类**写明的范围**是不是真的包含这份资料。两项都有把握才直接定，否则交给大模型。
2. 大模型按顺序判断，不跳步：先放正式分类 → 放不进再看草稿 → 都放不下才新建草稿。
3. 新建草稿要写全：一句话定义、包括什么、不包括什么、和最接近的两个正式分类的区别。程序在建之前检查：
   - 只能建在已有的一级领域下（新开一级领域由你直接定）；
   - 和已有的正式分类、草稿同名或同义的，并过去，不新建；
   - 你拒绝过的名字（包括换个说法）不再建；
   - 每个一级领域下的草稿数有上限。

**命名和粒度**
- 按**讲的是什么**（问题域或学科）划分；不按来源形式（视频、文档、课程、论文）、单个产品、单次收藏划分。
- 名字只表达一个主题。可以用“与”连接同一主题的两个方面，不能把两个能各自成类的主题拼在一起。
- 不带程度词（基础、入门、进阶）、不带含糊词（相关、其他、综合）、不带来源形式词（文档、教程、视频）。
- 粒度和表里现有的二级分类相当：能持续收到资料，又不至于大到和整个一级领域重合。

**草稿怎么显示**：一级领域加「（暂定：名字）」，例如 `科学（暂定：气候）`。草稿不进上面的表，index 里归在它的一级领域下。
`.memex/catalog.jsonl` 里写成 `draft:一级/二级`。

**转正**（门槛在 `.memex/config.toml` 的 `[taxonomy]` 里）：
- 足够多**不同的作品**（同一作品的重抓只算一份）；
- 来自足够多**不同的收录日**（一天收进一整个系列只算一次）；
- 再复核：把成员重新分一遍类（不告诉模型它们现在归哪），足够多的仍归这里。
- 三条都满足 → 待审核，收件箱里问你：批准（可以改名）/ 并入某个正式分类 / 拒绝。批准后写进上面的表，成员改归正式名字。

**其他出口**：并入（成员改归那个正式分类，以后同类也归那里）；拒绝（成员各自改归最合适的正式分类，这个名字以后不再提）；
过期（很久没有新资料，成员退回正式分类，收件箱知会一声）。

`memex catalog drafts` 看现状；`.memex/taxonomy-nodes.jsonl` 记录每个草稿的全部经过。
