这是一个知识库：wiki 由 Agent 从库主人收集的原始资料（raw/）编译而成。编写 Agent 每次编译后会在 inbox 里给主人留“待阅事项”，但写得太多，看不过来。
你的任务：把下面这些事项逐件分拣，只把真正需要主人本人拿主意的挑出来，并写成一眼能看懂、点一下就能决定的问题。

五类（kind）：
- decide：只有主人本人能定。满足其一：需要本人的意图、偏好、取舍（比如某个项目归属、页面要不要拆合、要不要改分类标准、某个方向要不要继续）；
  需要只有本人能看到的事实（本人的账号后台、做过什么、计划）；做错了代价大且不可逆。
  注意：能对照库里的 raw 或页面查清的、能查公开资料查清的，都不是 decide。
- agent：Agent 能自己查清、改好的：对照 raw 核实一句话、把来源没支持的说法改准或标注、关掉已经被后续来源解决的 ⚠️、按报告里已经写明且风险小的建议改页面、补互链。查证据的途径分别标出来：
  - 只读库里已有文件就能办：needs_web 和 needs_local 都写 false
  - 要先把公开资料（网页、论文、代码仓库 README、官方文档、视频）收进库里再对照着办：needs_web 写 true
  - 要先在这台电脑上取证：读本机的项目仓库、运行目录、日志、配置，跑只读的统计命令（wc、ls、git log），或者给库里某个视频补抽帧看画面：needs_local 写 true。这类事的答案是确定的事实，不需要本人拍板
- system：知识库流水线或工具本身的毛病，要改程序代码或配置才能解决的，以及要做有副作用的实验的。交给维护系统的人处理，不需要本人做知识上的判断。一件事里既有 agent 能办的、又有 system 的，按主要部分归类，agent_task 里只写 agent 能办的那部分。
- fyi：只是知会。编写 Agent 已经按默认做法处理了，不需要任何动作。
- done：正文里已经写明解决、关闭、被后来的批次回答了。

另外两类事情有专门的入口，在这里不要重复问：新分类的命名提议（分类程序会单独列出来），准入拿不准的候选（单独列）。报告里只是转述这两类的，归 fyi。

只根据下面的文字判断，不要打开任何文件。

每件都要输出全部字段（用不上的写空字符串、空数组、-1 或 false）：
- id：原样抄写
- why：一句话说明为什么归这一类
- decide 才填：
  - question：一句话的问题，大白话。没看过原报告、不记得编号也能懂；不要用“第 N 条”“本批”“编译推论”之类内部说法
  - context：两三句背景：涉及哪个页面或项目、两边说法分别是什么、为什么需要本人来定
  - options：2~4 个选项。label 很短（“合成一页”“保持两页”）；effect 写选了之后知识库具体会怎么变。不要放“以后再说”，界面上本来就有
  - recommend：建议选第几个（从 0 开始），没有倾向写 -1；recommend_why：一句话理由
- agent 才填 agent_task：一句话写清要达成什么结果、做到什么程度算完成（不要写具体命令）；以及 needs_web、needs_local
- pages：涉及的 wiki 页面名（去掉 [[ ]]），没有就空数组
