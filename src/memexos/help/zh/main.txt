memex：一个知识库（$vault）的命令行。任何 Agent 都用它查库、往库里收东西。

什么时候用
  问题涉及这个知识库覆盖的内容（$domains），或者库主人做过、定过、学过的事，先查库再回答。
  库里没有就直说，再用你自己的知识回答，并说明哪部分不来自库。

查库
  memex search "<问题>" --kw "<2~5 个关键词>"
      找相关页面，返回页面类型、来源分类、每页包含哪些关键词和摘录。关键词由你从问题里提炼（专有名词、术语），
      用页面所用的语言（$language），比只给问句准。第一次没找到：换一组关键词或换个说法再搜。
  memex get <页面名或路径>
      看一页全文（检索结果里的页面名、[[链接]] 或路径都行）。页面在 wiki/ 下：topics 主题综述（先看）、concepts 概念、
      entities 人和工具、sources 单个来源的摘要。
  memex catalog list --domain <领域> --evidence <证据强度>
      按领域、证据强度筛选来源。先用 memex catalog stats 看有哪些领域。
  memex feedback <页面> --kind incorrect|outdated|missing --why "<理由>"
      用页面回答时发现它写错了、过时了，或者缺了该有的内容，报告一声（有可靠出处就加 --evidence "<出处>"）。
      报告会先拿原始来源核实，确认后才走正常的编译和审校去改。库里本来就没有答案的问题不用报告（直接说没有），
      也不要用它保存新结论（见下面"往库里收东西"）。

往库里收东西（只写 raw/，编译和审校都是自动的）
  memex add-url <链接>     文章、推文、播客、视频
  memex add-video <链接>   视频（有字幕用字幕，没有就本地转写）
  对话里得出了值得留的结论、决策、踩坑、实测数据：先问对方要不要沉淀，同意后写会话快照（格式见 memex help snapshot）。

回答时的规则
  1. 带引用：说清用了哪一页（wiki/…）。关键事实可以顺着页面的 Sources 小节追到 raw/ 原始来源。
  2. 数字、单位、名称和原话照抄页面，不要改写。
  3. 只说页面支持的内容，不要说过头：页面写“目标约 95%”就不能说成“实测 95%”，写“绝大多数”就不能说成“全部”。
  4. 按来源的证据强度措辞（页面 frontmatter 里的 evidence）：一手实测、官方或原作者、学术研究可以当依据，说清是谁在什么条件下得出的；
     第三方转述写成“据某某转述”；个人经验观点写成“作者认为”；营销推广不能当证据。
     页面里标着 ⚠️ 待核实 或（编译推论）的，转述时保留这个标记；时效短的内容带上日期。
  5. 不要直接改 wiki/ 和 index.md（那里有编译和审校流程）；发现页面有问题用 memex feedback 报告。

更多
  memex <命令> --help    看某个命令的参数和例子（search、get、catalog、add-url、add-video、feedback、usage）
  memex help snapshot    会话快照的写法
  memex help admin       维护命令（编译、审校、采集、状态），一般由定时任务调用
